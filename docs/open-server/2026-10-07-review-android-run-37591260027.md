## Findings

1. BLOCKER — the guest runs slower under the proprietary stack. Logcat
   `Finish Transition` matched per tap: tap → SubSettings transition finished
   p50 OFF 1064-1361 ms vs ON 515-620 ms (tap+describe phase) and OFF
   1114-1246 vs ON 536-557 (gesture-tap phase, nothing after the tap). First
   frame OFF 515-670 vs ON 326-370. OFF-2 ran after both ON blocks and is
   still slow (arm effect, not drift). Host sampler: qemu CPU p50 250-262 % in
   OFF blocks vs 202-210 % in ON; `sim_server=1` only in OFF. No correct read
   on any arm ended before the transition finished (0/57), so time-to-correct
   ≈ transition done + polling. Residual after transition: OFF 596-746 ms, ON
   269-305 ms — only that is attributable to describe. Fix: publish the
   per-sample transition timeline per arm; establish what the proprietary
   stack runs in the background (simulator-server alive only in OFF: is the
   screen stream started by the harness/tool-server headless, or always by
   upstream?); scope any P5 claim to swiftshader on a 4-vCPU runner.
2. MAJOR — "stale = wrong answer" not supported: 22-27 of 29-32 OFF stale
   reads ended before the destination's first frame; they showed the screen
   as it was. No sign of a cached tree. Rename to "pre-transition/mixed".
3. MAJOR — P3/P4 wins come mostly from the describe after the gesture.
   Gesture alone (noDrain) OFF vs ON-im: swipe 292-298 vs 272 (−23, inside
   ±38), pinch 354 vs 317 (−37). Describe after: swipe 901 vs 839; pinch
   719-732 vs 216. ~500 ms of P4 is the describe. Inference: proprietary
   `getHierarchy` waits for idle after a gesture (720 ms vs 52 ms idle),
   contradicting the `settleToWaitTimeoutMs` comment that settle:false is
   like-for-like. Fix: gate the gesture-only rows with a CI; relabel drained
   rows "swipe+describe" / "pinch+describe".
4. MAJOR — P5 comparator chosen after seeing results (better of two ON
   rows, no multiplicity correction); settle:true row runs at the end of the
   block (not interleaved); 50 ms polling favours the arm with cheaper polls;
   proprietary path ignores `settle`; OFF tap → await-screen-idle → describe
   (what an OFF agent would do) was never measured. Honest tool-level
   number: correct-at-first-read ON settle:true 25-29/40 vs OFF 0-2/40.
5. OK — classifier symmetric: `destinationMarkers` identical in all 5
   blocks (14 destination / 16 root keys); fidelity Jaccard 1. OFF describe
   path matches upstream 0.27.0 (0f341762) except the fallback field and the
   fork-only `isAndroidTvCached` (saves one getprop per describe; favours
   OFF). gesture-tap OFF branch not fully diffed.
6. MAJOR (disclosure) — the reset gate never passed: all 489 resets timed
   out at ~5 s with `resumed=…Settings focused=false`; each reset was a fixed

   (`settings-reset.js:47,104`) not established.
7. MINOR — P2: Δ +1.3 ms, CI [1.0, 1.7], margin ±1.1: CI excludes zero and
