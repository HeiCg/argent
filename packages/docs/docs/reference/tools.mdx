Argent exposes its capabilities to the coding agent as MCP tools. You rarely call these by hand, but knowing what exists tells you what you can ask for.

Run `argent tools` to list them from the terminal, `argent tools describe <name>` for the full schema of one, and `argent run <name>` to invoke one directly.

## Devices and apps

| Tool                         | Description                                                                                   |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| `list-devices`               | List iOS simulators, Android emulators and devices, Chromium apps, and Vega (Fire TV) devices |
| `boot-device`                | Boot a simulator, emulator, or Vega Virtual Device, or spawn an Electron app                  |
| `use-device`                 | Set the default device for this agent session                                                 |
| `launch-app`                 | Open an app by bundle id (iOS) or package name (Android)                                      |
| `restart-app`                | Terminate then relaunch an app                                                                |
| `reinstall-app`              | Install or reinstall an app, clearing app data and runtime permissions                        |
| `open-url`                   | Open a URL or URL scheme on the device                                                        |
| `settings-permissions`       | Grant, deny, or reset a runtime permission without navigating the Settings UI                 |
| `rotate`                     | Set the device orientation to portrait or either landscape                                    |
| `fold`                       | Fold or unfold a foldable iOS simulator to a posture or a hinge angle                         |
| `shake`                      | Shake the device                                                                              |
| `button`                     | Press a hardware button: home, back, power, volume, app switch, action button                 |
| `tv-remote`                  | Press a TV remote or D-pad button on Apple TV, Android TV, or Vega                            |
| `stop-simulator-server`      | Stop the transport session for one device and free its resources                              |
| `stop-all-simulator-servers` | Stop every service a device owns: simulator servers, native devtools, TV daemons              |
| `stop-metro`                 | Stop the Metro bundler listening on a given port                                              |

`use-device` sets the default device of the agent session. The Argent MCP server answers this tool. The tool server does not receive it.

- `use-device { udid }` sets the default. Get the id from `list-devices`.
- `use-device { clear: true }` removes the default.

A device tool called without its required device id (`udid`, `device_id` or `device`) uses the default. An id in the call always has priority over the default. The tool schemas show a required device id as optional for this reason. Argent does not fill an optional device id. For example, `flow-execute` without `device` still selects the device automatically, and `boot-device` without `udid` boots the device that its other arguments name.

The last of these events sets the default:

- a `use-device { udid }` call,
- a successful `boot-device` call, which sets the booted device,
- a successful call with an explicit `udid` or `serial`. A `stop-` tool is not such a call.

A successful `stop-` tool clears the default when the tool names the default device. An unscoped `stop-all-simulator-servers` also clears it.

The last line of the `list-devices` result names the default device and the event that set it, for example `Default device: emulator-5554 (boot-device)`. If the device is not in the list, the line ends with `— not in this list`. Each agent session has its own default. Two sessions on the same tool server do not share it.

If there is no default and the tool requires a device id, the call fails with this error: `No device selected. Call use-device {udid} or pass udid explicitly; list-devices shows the ids.`

Argent drives a foldable iOS simulator, for example the iPhone Duo. `list-devices` marks it with `foldable: true`. `fold` moves the hinge to a posture (`closed`, `half-open` or `open`) or to an angle from 0 to 180 degrees.

- Closed, the cover panel shows the UI. Half-open and open, the inner panel shows the UI. The panel that shows the UI is the active panel.
- All tools use the active panel. This is also true after a fold made outside Argent.
- The coordinates and the screenshot size change with the panel.
- A video keeps the size of the panel where the recording started. Argent keeps the proportions of the other panel and adds black bars.
- A fold between two angles that are not 0 or 180 can keep the current panel. To change panels, fold to `closed` or `open`.
- Unfolded, the UI is landscape. `rotate` sets the orientation of the device, not of the UI. `Portrait` gives a landscape UI.
- If Argent cannot find the active panel, it uses the cover panel. The tool result then has a warning.

Argent supports physical iPhones; physical iPads are not supported yet. `list-devices` shows a physical device as an iOS entry with kind `device`. The state is `connected` only while the device is attached by USB cable; Argent controls physical devices over the cable and does not use Wi-Fi. The state is `paired` when the device is paired but not reachable now. Argent never selects a physical device automatically: name its udid. A `paired` device cannot be driven until it is connected by cable again. See [Physical iOS devices](/docs/features/physical-ios-devices) for the requirements, the signing model, and the app-scoped interaction contract.

## Inspecting the screen

| Tool                | Description                                                                      |
| ------------------- | -------------------------------------------------------------------------------- |
| `screenshot`        | Capture the device screen                                                        |
| `describe`          | Get the accessibility / DOM element tree for the current screen                  |
| `screenshot-diff`   | Compare two PNG screenshots and return a visual-diff summary                     |
| `await-screen-idle` | Block until the screen has rendered content and stopped changing                 |
| `await-ui-element`  | Block until a UI element reaches an expected state, instead of polling in a loop |

### Execution incident line (Android open server)

On Android with the open device server active, `describe` prepends one line to
its output after a failed verified gesture on the same device. The line reports
the last failure so the agent sees it on the next read:

```
incident: <tool> <code> ×<n> — <hint>
```

`<tool>` is the tool that failed. `<code>` is the failure code, for example
`verify_not_found`. `<n>` is the number of failures in a row. `<hint>` tells the
agent what to change:

| Code               | Hint                                        |
| ------------------ | ------------------------------------------- |
| `verify_not_found` | re-describe and pick a visible label        |
| `verify_ambiguous` | add a second field to the selector          |
| `verify_mismatch`  | your coordinates point at the named element |

After three failures in a row the line adds `consider a different approach`.
The next successful gesture clears the line. Argent keeps this state in memory
only. It does not survive a tool-server restart and it adds no device call.

### Empty tree and fallback (Android open server)

When no window is active, the open device server reads the screen again for up to
500 ms. If no window becomes active, `describe` returns an empty tree with
`treeEmpty: true` and `treeEmptyReason`. When the open device server fails,
`describe` uses another backend and returns `backend: "proprietary-fallback"` and
`fallbackReason`.

When the tree has a root but no elements, `describe` reads the screen again up to
2 times, 50 ms apart. If all 3 reads have no elements, `describe` returns the
root with no elements and a hint, without `treeEmpty`. The hint tells the agent
that the screen can be mid-transition. It also tells the agent to run `describe`
again or `await-screen-idle`. A `settle` of `true` or of more than 0 ms gives one
read only.

The `settle` parameter makes `describe` wait for UiAutomator idle before the
read, for a maximum of 500 ms. A number sets a different maximum in ms. This
wait does not confirm that the screen is quiet. To wait for the end of a
transition, use `await-screen-idle`.

### The same steps on several devices

`run-on-devices` runs one list of steps on 2 to 8 devices in one call. The
devices run in parallel. Each device runs the steps with the `run-sequence`
rules. Use `run-sequence` for one device.

| Argument             | Type                  | Meaning                                                                                                                               |
| -------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `udids`              | string array          | The device ids from `list-devices`. 2 to 8 ids. Each id must occur one time.                                                          |
| `steps`              | array                 | The steps. The shape and the allowed tools are the same as in `run-sequence`.                                                         |
| `screenshots`        | `"none"` or `"final"` | Default `"none"`. `"final"` takes one screenshot on each device right after its last step. It does not wait for the screen to settle. |
| `stopOnFirstFailure` | boolean               | Default `false`. `true` stops all devices after a failure on one device.                                                              |

Argent refuses the call before a device runs a step when:

- a device id occurs more than one time in `udids`,
- a step names a tool that `run-sequence` does not allow.

Argent adds the id of each device to the arguments of each step on that device.
Do not put `udid` in the step arguments. A failure on a device stops the
remaining steps on that device. An `await-ui-element` condition that is not met
also stops them. With `stopOnFirstFailure` set to `false`, the other devices
continue. With `true`, the other devices stop before their next step. A step
that runs at that time completes.

Two `run-on-devices` calls that use the same device do not mix their steps on
that device. The second call waits on that device until the first call has
finished its steps on that device.

Coordinates are normalized (0 to 1) on each device. The point
`{ x: 0.5, y: 0.9 }` is the bottom center of each screen. The element at that
point can be different on two screen sizes or two platforms. Use
`await-ui-element` to confirm a screen before a tap.

The tool returns `{ results, okCount, failedCount }`. `results` has one entry
for each device, in the order of `udids`:

| Field             | Meaning                                                                   |
| ----------------- | ------------------------------------------------------------------------- |
| `udid`            | The device id.                                                            |
| `ok`              | `true` when all steps completed on the device.                            |
| `steps`           | The result of each step that ran, the same as in `run-sequence`.          |
| `error`           | The step and the error that stopped the device. Absent when `ok` is true. |
| `durationMs`      | The time in ms that the device used for the steps.                        |
| `screenshot`      | The final screenshot of the device. Only with `screenshots: "final"`.     |
| `screenshotError` | The error of the final screenshot, when the capture failed.               |

The result contains each step result of each device, so the result can be
large. With `screenshots: "none"`, the result has no image. With `"final"`, the
result has one image for each device. When a step contains a `{{secret:...}}`
placeholder, Argent does not take the final screenshots.

### Gesture bursts on the Android open server

`gesture-sequence` runs a burst of steps back-to-back in one on-device call. The
agent uses it when a transient element must survive between steps. One example is
a bottom sheet that the agent dismisses and then a control the sheet revealed that
the agent taps before the sheet animates away. The tool needs the Android
open-device-server. Other targets use `run-sequence`.

Each step names a `kind` and its parameters:

| `kind`  | Parameters                                                                  |
| ------- | --------------------------------------------------------------------------- |
| `tap`   | `x`, `y` (normalized 0–1), or `target: { index, version }`; `clickCount?`   |
| `swipe` | `fromX`, `fromY`, `toX`, `toY` (normalized 0–1); `durationMs?`; `momentum?` |
| `key`   | `key` (for example `enter`, `back`, `home`)                                 |
| `wait`  | `waitMs` (a pause on the device between two steps)                          |

Every step also takes an optional `delayMs`. The device waits that long after the
step, before the next one. The tool returns `{ completed, total, totalMs, steps }`.
Each entry in `steps` reports `{ kind, success, dropped?, ms, skipped? }`. On the
first failing step the device skips the remaining steps and reports them as
`skipped`, so the burst stops the moment a dismiss or a tap misses.

A burst allows at most **one** `target` index step. Every index resolves against
the one screen snapshot read before the burst. A second index step would act on a
screen an earlier step already left, so Argent refuses it with
`stale_index_in_burst`. Use an index step first, and tap later transient controls
by coordinate.

### Element-index taps

The `describe` tool has a `tier` parameter on the Android open-device-server path.
The `index` tier renders one `[i] label (role)` line per interactive element, with
a per-screen index and a header that names the screen version. The tier lists the
**active window only**, so an element under a dialog or the keyboard, or past the
node cap, does not appear. The header states the scope and flags a truncated list.

The agent taps an element by its index. It passes `target: { index, version }` to
`gesture-tap` or to a `gesture-sequence` `tap` step. Argent reads the live screen
and resolves the index against the same snapshot version. Argent refuses the tap
with `stale_index` when the screen moved since the `describe`, and with
`index_out_of_range` when the index is not on the current screen — no tap is issued
on a refusal.

### Verified tap and swipe (Android open server)

`gesture-tap` and `gesture-swipe` accept an optional `verify` parameter. `verify`
applies only on Android when the open device server is active. On iOS or the
proprietary Android path, Argent refuses a `verify` request with
`verify_unsupported` and issues no tap. When `verify` is absent, the tap and
swipe paths do not change.

With `verify`, the coordinates are optional. Omit `x` and `y` (or `fromX` and
`fromY` for a swipe) to tap or start at the resolved element center. Supply them
to cross-check the resolved element.

`verify` takes a `selector` and an optional `tolerancePx`:

| Field         | Type   | Meaning                                                                         |
| ------------- | ------ | ------------------------------------------------------------------------------- |
| `selector`    | object | The element to confirm on the live screen. See the fields below.                |
| `tolerancePx` | number | Slack in pixels around the matched element for the coordinate check. Default 0. |

The `selector` uses the screen-selector grammar. Each string field is a bare
string for an exact match, or an object `{ contains }`, `{ equals }` or
`{ regex }` with an optional `caseInsensitive`.

| Selector field       | Meaning                                         |
| -------------------- | ----------------------------------------------- |
| `id`                 | Resource id.                                    |
| `text`               | Visible text.                                   |
| `class`              | Class name.                                     |
| `index`              | Pick the Nth match, 0-based.                    |
| `visible`            | Require a visible node.                         |
| `containsDescendant` | A nested selector that a descendant must match. |

Argent runs a `query` on the live accessibility tree before it injects the
gesture. Argent resolves one unique node with a fixed precedence: exact id, then
exact text, then exact content description, then a single contains match, then
class. Fields the server matches directly — `regex`, `containsDescendant`,
`visible`, `index` and a contains-only `id` — resolve the same way: when the
server returns exactly one node, Argent taps it. On a unique match Argent taps
the center of the element bounds. For a swipe, Argent starts the swipe at the
center of the element bounds and keeps the end point as given.

The reply reports `verified: true`, `resolvedBounds`, `version` and `verifyMs`.
`verifyMs` is the time of the one `query` call. Argent refuses without injecting
in these cases:

| Error code           | Cause                                                                                                                                                                         |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verify_not_found`   | No element matched the selector. The reply carries no bounds.                                                                                                                 |
| `verify_ambiguous`   | More than one element matched. The reply lists up to five of the colliding candidates.                                                                                        |
| `verify_mismatch`    | The x and y fall outside the matched bounds ± `tolerancePx` (default 0). The reply returns the requested coordinates and the matched element. Only when x and y are supplied. |
| `verify_unsupported` | The device is not on the Android open path (iOS or the proprietary backend). Argent issues no tap.                                                                            |
